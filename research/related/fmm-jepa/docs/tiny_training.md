# Tiny ImageNet training and exact recovery

The reusable module is `fmm_jepa.tiny_training`, stored in `fmm_jepa/tiny_training.ipynb`. The existing bootstrap imports only tagged `ahr-export` definition cells. No experiment starts on import. Tests live in `fmm_tests.test_training_resume`.

`initialize_paired_models(config, artifact_dir)` returns `(models, parameter_counts, initialization_metadata)`. Both models start fresh on CPU. The ViT nonmixer context scaffold and entire conventional predictor are copied to FMM where shapes match, with independent tensor storage. Each teacher is then recopied from its own context encoder. Initial artifacts are pure state dictionaries at `initialization/{vit,fmm}_initial_teacher.pt` and `initialization/{vit,fmm}_initial_model.pt`, accompanied by SHA256 hashes. Existing initialization files are validated before use; orphan or changed files are refused.

`training_protocol(config)` resolves the optimizer/update policy for registration. `pretraining_forward(model,batch)` is the actual runner entry into JEPA and does not read labels. `run_model(kind, config, dataset_bundle, artifact_dir, checkpoint_dir, protocol, model=None, stop_after=None, diagnostic_callback=None)` runs smoke and pilot through the same implementation. The optional `stop_after` bounds this invocation while keeping the registered final schedule budget unchanged, which is essential for recovery tests. The returned model is moved to CPU to isolate sequential GPU workloads.

AdamW uses learning rate 0.0003 and decay 0.05 by default. Biases and all one-dimensional parameters, including normalization scales, receive zero weight decay; the exact names are saved. The first ceil(5% of the budget), at least one, successful updates linearly warm up. Cosine learning-rate decay reaches zero at the final update. Cosine EMA momentum increases from 0.996 at update 1 to 1.0 at the final update. The final zero learning rate and unit EMA endpoint are explicit registered endpoints. Every accumulation microbatch has the same size and its loss is divided by the accumulation count. Partial accumulations are rejected. The data stream can cross epoch boundaries to deliver a full effective batch.

Only FP32 is supported. The teacher is frozen, excluded from the optimizer, and remains in evaluation mode. Losses, relevant activations, gradients, and updated parameters must remain finite. Clipping uses global norm 1.0; logged global norms precede clipping, while branch gradient norms follow clipping. Invalid pre-update attempts consume the delivered examples, do not advance the schedule or EMA, and count toward the failure cap. Invalid post-update state stops immediately, preserving the last valid checkpoint. Labels are present in dataset batches for audit/evaluation but are never passed into the JEPA model.

The consumed sampler uses a SHA256-derived local generator for each epoch permutation. Augmentation and masking use the dataset module's stateless per-sample/per-occurrence streams. No DataLoader workers or prefetching are used. The cursor records delivered examples, including unsuccessful attempts. Global Python, NumPy, CPU Torch, and visible CUDA RNGs are additionally saved. Initialization and diagnostics restore global RNG states after running. Current FMM operators retain geometry and detached scalar statistics only; no feature-dependent computation graph cache persists between batches.

Checkpoints are atomic, fsynced Torch payloads with an atomic manifest. They contain context, teacher, predictor, optimizer, successful-update scheduler, EMA position, scaler policy, all RNG states, stream policy/seeds, consumed cursor, attempted/successful update counts, metrics, traces, config, protocol, dataset/split/source identities, and execution compatibility. One writer holds a filesystem lock. Save boundaries are initial step 0, every configured 5 successful updates (capped at 250), epoch crossings, final invocation, and at most 15 minutes between completed updates. The latest two valid resumable checkpoints and best-loss recovery checkpoint are retained. The primary comparison always uses the final registered-budget checkpoint; best-loss retention is not a selection procedure.

Resume by calling `run_model` with the identical configuration, protocol, dataset manifests, source/environment identities and checkpoint path. The function verifies every retained checkpoint hash, restores fresh state and the consumed sampler, and verifies metrics/schedule positions. Invalid manifests, hashes, mismatched software/device settings or orphan checkpoints are refused. Mid-update interruptions recover the previous complete checkpoint and replay that interval; a separate interruption journal reports the interrupted invocation. No claim of exact recovery across differing hardware/software is made.

`run_real_resume_certificate(config,bundle,artifact_dir,checkpoint_root)` uses actual Tiny ImageNet images, CPU FP32 with one thread and deterministic algorithms enabled, width 32/depth 1/order 2, microbatch 2 and accumulation 2. Each architecture runs four successful updates uninterrupted and in a two-plus-two trajectory restored into a fresh model object. The certificate compares exact model/optimizer/scheduler/RNG states, losses, data/augmentation/mask traces and the next sample IDs; it separately corrupts a copied checkpoint and requires refusal. This is an equivalent fresh-state test in one process, not a cross-device guarantee. `run_training_accounting_tests(config,bundle)` compares accumulated gradients with a full batch and checks optimizer exclusions and schedule positions.

Training timing uses actual updates. CUDA event pairs cover microbatch compute and clipping/optimizer/scheduler/EMA, and are synchronized when checkpoints are flushed instead of adding a timer synchronization after every normal update. CPU timers measure the same compute path. Data/preprocessing is timed separately and included in total step time. Summaries exclude the first two successful updates and report median/interquartile timing and throughput. Peak allocated GPU memory is PyTorch live tensor allocation for the current sequential model run, not total device/context or reserved allocator memory. Checkpoint I/O and diagnostic time are excluded from step times and included in overall invocation wall time. Models, precision, batches, masks and token grids must be matched when interpreting results.

An earlier exploratory CPU two-thread resume comparison produced identical losses and data traces, but FMM model tensors differed by at most 3.28e-7. That failed bitwise fixture is preserved in `artifacts/notebook_01/development_verification/threaded_resume_observation.json`; the strict certificate explicitly uses one thread and deterministic algorithms. It does not extend a bitwise guarantee to the ordinary two-thread or CUDA profiles.
